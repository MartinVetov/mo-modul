# Как работим по проекта

Кратки правила, за да не си пречим. Всичко останало е в `README.md`.

## Първо пускане при нов колега

```bash
git clone https://github.com/<организация>/mo-modul.git
cd mo-modul
cp config.sample.php config.php      # Windows: copy config.sample.php config.php
```

После в phpMyAdmin, **в базата на ВИС**: `sql/01_module_schema.sql`, след това `sql/02_module_seed.sql`.

**`config.php` никога не влиза в git** — там са паролата за базата, пътят до Laravel проекта и AI ключът.
Ако някой го качи по невнимание, сменете паролите и ключа веднага.

## Клонове

| Клон | За какво е |
|---|---|
| `main` | това, което работи на училищния сървър. Само проверен код. |
| `razrabotka` | текущата работа. Оттук се сливат нещата в `main`. |
| `feature/<кратко-име>` | една задача — например `feature/sravnenie-godini` |

Работният цикъл:

```bash
git checkout razrabotka
git pull
git checkout -b feature/eksport-word
# ... работа ...
git add -A
git commit -m "Експорт на доклада във Word"
git push -u origin feature/eksport-word
```

После отваряте Pull Request към `razrabotka` и някой друг го преглежда.
Правило: **никой не слива собствения си PR без поне един преглед.**

## Съобщения при commit

На български, в сегашно време, едно изречение по същество:

- добре: `Добавя филтър по паралелка в обобщението`
- добре: `Поправя изчислението на % слаби при нула оценки`
- зле: `промени`, `fix`, `ъпдейт`

## Промени по базата данни

Никога не редактирайте `sql/01_module_schema.sql` при вече работеща система — колегите
и сървърът вече имат стари таблици. Вместо това добавете нов файл:

```
sql/migrations/2026-09-15-dobavya-kolona-zabelejka.sql
```

с `ALTER TABLE ...` и ред в него кой и защо го е добавил. В PR-а опишете, че
има миграция, за да я пуснат всички.

## Кой какво поема

Отворете **Issues** в GitHub и опишете задачата, преди да пишете код. Етикети,
които ползваме: `грешка`, `нова функция`, `база данни`, `спешно`, `за обсъждане`.

## Какво НЕ качваме

- `config.php` и всякакви пароли, ключове, токени
- лични данни на ученици и колеги, включително тестови файлове с реални имена
- архиви на реалната база данни
- качени от учители файлове (`storage/uploads/`)

Ако имате нужда от примерни данни, използвайте `sql/02_module_seed.sql`.
**Никога не качвайте дъмп на реалната таблица `users`** — тя съдържа имейли и хешове на паролите на колегите.
